# Сторонние компоненты: проверяемые факты и открытые вопросы

Это технический аудит, а не юридическое заключение. Здесь записано, что
проверено и как именно, что из этого следует по текстам лицензий, и какие
вопросы остаются для юриста. Дата аудита: 2026-11-07, состояние после релиза
v0.1.0-alpha.11.

Источник истины по версиям и хешам — `licenses/third-party-sources.json`.
Перечень для пользователей — `THIRD_PARTY_NOTICES.md`.

### Происхождение бинарных файлов движка

Проверено вручную при аудите: скачаны официальные релизы и сравнены SHA-256.

- `winws.exe`, `cygwin1.dll`, `WinDivert.dll`, `WinDivert64.sys` из Flowseal
  1.10.4 побайтно совпадают с `zapret-v72.9/binaries/windows-x86_64/` релиза
  [bol-van/zapret v72.9](https://github.com/bol-van/zapret/releases/tag/v72.9)
  и с его `sha256sum.txt`.
- `WinDivert.dll` и `WinDivert64.sys` побайтно совпадают с `x64/` в
  [WinDivert-2.2.2-A.zip](https://github.com/basil00/WinDivert/releases/tag/v2.2.2).
  Ресурс версии драйвера: «WinDivert 2.2 driver», «Copyright © Basil 2011-2022».
- `cygwin1.dll`: ресурс версии `3.4.10`, «Copyright © Cygwin Authors
  1996-2023», «Red Hat». В строках файла — пути официальной сборки
  `cygwin-3.4.10-1.x86_64`. Значит, это неизменённая официальная сборка
  Cygwin 3.4.10.
- `winws.exe` импортирует `cygwin1.dll` и `WinDivert.dll` через таблицу
  импорта (проверено `objdump -p`). Значит, это обычное динамическое связывание
  при загрузке: DLL ищутся в каталоге exe. zlib связан статически
  (`nfq/Makefile`: `-lz`), это лицензия zlib без требований к бинарникам.
- Тексты `licenses/Flowseal-LICENSE.txt`, `zapret-LICENSE.txt` и
  `WinDivert-LICENSE.txt` побайтно совпадают с upstream: `LICENSE.txt` тега
  Flowseal `1.10.4`, `docs/LICENSE.txt` zapret v72.9 и `LICENSE` WinDivert 2.2.2.

## 3. WinDivert

**На какой лицензии основано распространение.** WinDivert распространяется
по LGPLv3 или GPLv2 на выбор получателя (`LICENSE` WinDivert 2.2.2; README
релиза называет LGPLv3; заголовки исходников — «LGPL version 3, or (at your
option) any later version»). Bridge выбирает **LGPLv3**:

- Код Bridge (MIT) не связан с WinDivert: служба запускает `winws.exe`
  отдельным процессом. Связан с WinDivert только `winws.exe` (MIT), который
  импортирует `WinDivert.dll`.
- Для исходников LGPLv3, через GPLv3 §6(d), допускает ссылку на сервер
  третьей стороны с понятными указаниями рядом с бинарником. GPLv2 §3 требует
  «эквивалентного доступа из того же места», что для GitHub Releases этого
  проекта означало бы зеркалировать исходники у себя.

**Требования LGPLv3 к библиотеке как таковой** (§§0–2, через GPLv3 §6):
передать текст лицензии и предоставить Corresponding Source объектного кода.

- Текст: `WinDivert-LICENSE.txt` (с текстами LGPLv3, GPLv3, GPLv2) и отдельные
  `LGPL-3.0.txt`, `GPL-3.0.txt`.
- Исходник: точный тег `v2.2.2` и коммит `1789526e…` в официальном
  репозитории, архив тега на GitHub. Указано в `THIRD_PARTY_NOTICES.md` и
  `licenses/third-party-sources.json`, оба лежат рядом с бинарником в
  установке. Сборочные скрипты (`msvc-build.bat`, `wddk-build.bat`) входят в
  этот исходник.

**§4 LGPLv3 (Combined Works).** Это обязанности того, кто передаёт
«Combined Work», то есть `winws.exe` вместе с библиотекой.

- (a), (b) — уведомление о том, что используется LGPL-библиотека, и тексты
  GPL и LGPL: есть.
- (d)(1) — подходящий механизм разделяемых библиотек: `winws.exe` загружает
  `WinDivert.dll` из своего каталога через таблицу импорта и будет работать с
  изменённой совместимой по интерфейсу версией.
- Препятствием могла бы быть проверка SHA-256 в Bridge: служба запускает
  движок только при совпадении хешей с `bundle-manifest.json`. Проверено:
  - манифест встроенного набора лежит в каталоге установки, доступном на запись
    только администраторам, и не подписан;
  - администратор может заменить DLL и записать её хеш в манифест;
  - служба по хешу манифеста создаёт новую копию движка и запускает её;
  - тихая подмена без изменения манифеста отклоняется.

  Порядок описан в `THIRD_PARTY_NOTICES.md` («Replacing LGPL components») и
  закреплён тестом `a_replaced_lgpl_library_is_used_once_its_hash_is_recorded`
  (`crates/bridge-helper/src/bundles.rs`). Проверку хешей отключать не
  понадобилось.
- (e) Installation Information нужна, только если это требует GPLv3 §6, то
  есть для «User Product». Обычный ПК с Windows и программа для него к этому,
  по распространённому толкованию, не относятся — см. вопрос В2.

**Драйвер.** `WinDivert64.sys` передаётся с исходной подписью. Чтобы Windows
загрузила свою сборку драйвера, нужна подпись, которую принимает Microsoft,
или тестовый режим подписи. Это ограничение платформы, а не Bridge: Bridge не
добавляет технических мер, мешающих замене (см. вопрос В2).

## 4. Cygwin

**Версия:** `cygwin1.dll` 3.4.10, официальная сборка пакета `cygwin-3.4.10-1`
(x86_64), без изменений.

**Лицензия** (https://cygwin.com/licensing.html): API-библиотека Cygwin
(`winsup`) — LGPLv3 или новее, плюс Cygwin Linking Exception. Исключение
разрешает связывать `libcygwin.a`, `crt0.o`, `gcrt0.o` с независимыми модулями
и передавать полученный исполняемый файл на любых условиях без выполнения
§4 LGPLv3.

**Применимость к нашей конфигурации.**

- `winws.exe` собран Cygwin GCC и связан со стартовым кодом и библиотекой
  импорта Cygwin (`libcygwin.a`). Сам `winws` не основан на коде Cygwin
  (MIT, bol-van) — по смыслу исключения это «независимый модуль». Значит,
  `winws.exe` можно передавать без требований §4.
- Исключение **не освобождает саму `cygwin1.dll`**. Это объектный код
  LGPLv3-библиотеки, и при её передаче действуют §§0–2 LGPLv3 и GPLv3 §6:
  - текст LGPL и GPL — есть;
  - уведомление — есть, `licenses/Cygwin-LICENSE.txt` (официальный текст
    условий и исключения, точная версия, ссылки на исходник);
  - Corresponding Source — официальный репозиторий newlib-cygwin, тег
    `cygwin-3.4.10`, коммит `89a1e4a5…`, зеркало и архив на GitHub.
- Замена DLL совместимой сборкой — тот же порядок, что для WinDivert.
  Исключение делает его необязательным для `winws.exe`, но он и так работает.

**Особенность.** Исходного пакета `cygwin-3.4.10-1-src.tar.xz` на зеркалах
Cygwin больше нет: они хранят только текущие версии, проверено на
mirrors.kernel.org. Есть тег в официальном git, его зеркало и архив тега на
GitHub. В точный исходный пакет Cygwin, кроме дерева newlib-cygwin, входят
сборочные файлы cygport — см. вопрос В1.

| Компонент | Где исходник | Достаточно ли |
|---|---|---|
| WinDivert 2.2.2 (LGPLv3) | тег и коммит upstream, архив GitHub; указано рядом с бинарником | по GPLv3 §6(d) ссылка на сторонний сервер допустима, но распространитель отвечает за доступность исходника, пока это требуется. Сейчас исходник доступен, но гарантии нет — **В1** |
| Cygwin 3.4.10 (LGPLv3+) | тег и коммит upstream, зеркало и архив GitHub | то же; исходного пакета на официальных зеркалах уже нет — **В1** |
| winws, Flowseal, tg-ws-proxy, Python-пакеты, крейты и npm | MIT/BSD/Apache/PSF/MPL | исходник не требуется (MPL — только сообщить, где он: сделано) |

**Вывод.** Уведомления и тексты лицензий теперь полные. Указания, где взять
исходный код LGPL-компонентов, лежат рядом с бинарниками. Технических
препятствий для замены LGPL-библиотек нет. Не решено, как гарантировать
доступность исходников независимо от третьих лиц (В1). Пока этот вопрос не
решён, нельзя утверждать, что требования LGPL к исходникам выполнены
полностью.

## 6. Открытые вопросы (нужна юридическая проверка или решение владельца)

- **В1. Своя копия исходников LGPL.** Самый надёжный вариант по GPLv3 §6(d) —
  хранить точные архивы исходников WinDivert 2.2.2 и Cygwin 3.4.10 (вместе с
  cygport) на своём сервере, например отдельным релизом
  `sources-flowseal-1.10.4` в этом репозитории, и ссылаться на них из
  уведомлений. Альтернатива — письменное предложение (§6(b)) на 3 года. Оба
  варианта — публичное действие или обязательство владельца проекта, поэтому
  в этом PR не выполнены.
- **В2. «Installation Information» и подпись драйвера.** Считается ли
  требование Windows к подписи драйвера препятствием по LGPLv3 §4(e) или
  GPLv3 §6 для обычного ПК (не «User Product»)? По тексту лицензии требование
  относится к User Products; окончательную оценку должен дать юрист.
- **В3. Bridge и winws — «агрегат» или «Combined Work».** Аудит исходит из
  того, что запуск `winws.exe` отдельным процессом — это агрегат, а не
  комбинированная работа с WinDivert или Cygwin. Это общепринятая позиция
  (GPL FAQ, «mere aggregation»), но это толкование, а не проверка.
- **В4. Пакеты без файла лицензии.** У 7 пакетов (`alloc-stdlib`,
  `selectors`, `webview2-com`, `webview2-com-macros`, `webview2-com-sys`,
  `@uiw/codemirror-extensions-basic-setup`, `@uiw/react-codemirror`) в
  опубликованном архиве нет файла лицензии. Для них указаны лицензия и
  источник; копий их copyright-строк в установке нет. Можно добавить тексты
  из репозиториев этих проектов вручную.
- **В5. Microsoft Distributable Code.** `vcruntime140*.dll` в движке
  Telegram распространяются по условиям, приведённым в `Python-LICENSE.txt`.
  Одно из них — требовать от распространителей и конечных пользователей
  согласия с условиями, защищающими этот код не меньше, чем условия
  Microsoft. Как это обычно делают проекты на PyInstaller — вопрос для юриста.
- **В6. NOTICE-файлы Apache-2.0 внутри статически связанного кода**
  (например, OpenSSL в `cryptography`). Тексты лицензий есть. Есть ли у этих
  версий NOTICE-файлы, которые нужно передавать, отдельно не проверялось.

## 7. Автоматические проверки

- `scripts/third-party-licenses.mjs` (сборка, Windows CI): уведомления всех
  крейтов и npm-пакетов. Ошибка, если у пакета нет лицензии или её нет в
  списке разрешённых. Тест разбора SPDX — в Frontend CI.
- `scripts/ci/verify-installer.ps1` (Windows CI и релиз):
  - все файлы `licenses/` установлены без изменений;
  - хеши четырёх файлов движка совпадают с `third-party-sources.json`, а
    `THIRD_PARTY_NOTICES.md` содержит их хеши и коммиты исходников. Если при
    обновлении Flowseal бинарники изменятся, проверка не пройдёт, пока
    документация не будет обновлена;
  - есть `licenses/third-party/` этой сборки и лицензия PyInstaller.
- `tests/third-party.test.ts` (Frontend CI): согласованность
  `third-party-sources.json`, `THIRD_PARTY_NOTICES.md` и `flowseal.lock.json`;
  ссылки README на релиз ведут на установщик и `SHA256SUMS.txt` приложения,
  а не на `releases/latest`.
- Тест службы `a_replaced_lgpl_library_is_used_once_its_hash_is_recorded`.

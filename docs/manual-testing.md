# Ручное тестирование на Windows 11

Автоматические тесты проверяют логику (парсер, валидацию, рендер, diff, хранение,
подписи) и сборку. Реальная работа обхода, драйвера и голоса проверяется только вручную
на Windows 11 x64 у провайдера с DPI-блокировкой Discord.

## 1. Установка
- [ ] Установщик запускается, запрашивает права администратора, ставит в Program Files.
- [ ] `services.msc`: служба «Discord Bridge Helper» — «Выполняется», тип запуска «Автоматически».
- [ ] Ярлык в меню «Пуск»; приложение запускается **без** UAC.
- [ ] «О программе»: версии приложения, Flowseal 1.10.4, winws v72.9, служба.

## 2. Discord
- [ ] Discord найден, версия показана; при отсутствии — кнопка «Скачать Discord».
- [ ] «Запустить Discord» открывает клиент; повторное нажатие не создаёт второй экземпляр.
- [ ] Неверный путь в настройках отклоняется с понятной ошибкой.

## 3. Обход и стратегии
- [ ] Без обхода: Диагностика → HTTPS к discord.com — ошибка/тайм-аут (на заблокированной сети).
- [ ] Включить обход (general): в «Диспетчере задач» появился один `winws.exe`; Диагностика → HTTPS ✓.
- [ ] Discord загружает каналы, сообщения, картинки.
- [ ] **Голос**: зайти в голосовой канал → «Голосовая связь подключена»; слышно собеседника.
      Отметить результат кнопкой «Голос работает» / «Не работает».
- [ ] Переключение стратегии из главного окна и из трея — остаётся один `winws.exe`.
- [ ] Стратегия с ошибкой (испортить в редакторе) не запускается, показывает ошибки.
- [ ] Auto: запускается, показывает журнал, останавливается по «Отменить».
- [ ] Остановка обхода — `winws.exe` исчезает.

## 3a. Транзакции и откат (alpha.4)
- [ ] Откат после сбоя winws проверен модульными тестами (`crates/bridge-helper/src/txn.rs`).
      Надёжного способа вызвать сбой winws на реальной системе без вмешательства
      в защищённые файлы службы пока нет; если сбой встретится в работе — убедитесь,
      что показан диалог «прежняя конфигурация восстановлена» и в Диспетчере задач
      ровно один `winws.exe`.
- [ ] Переключение A → B → A несколько раз подряд: всегда один `winws.exe`,
      в `%ProgramData%\DiscordBridge\runtime` один каталог `gen-N`.
- [ ] Auto: запустить и отменить на 2-й попытке → работает исходная стратегия.
- [ ] Auto при выключенном обходе, отмена → обход остаётся выключенным.
- [ ] Во время Auto переключить стратегию в трее → отказ с объяснением.
- [ ] Закрыть приложение («Выход») во время Auto → после перезапуска пробный режим
      откатан, работает исходная конфигурация.

## 3b. Несколько пользователей
- [ ] Пользователь A включает обход. Пользователь B (без прав администратора,
      быстрое переключение пользователей) пытается выключить — отказ «управляет
      другой пользователь». B «от имени администратора» — разрешено.
- [ ] A выходит из системы → B может управлять обходом.

## 4. Конфликты
- [ ] Запустить оригинальный Flowseal `general.bat` → включить обход в Discord Bridge →
      диалог конфликта; чужой `winws.exe` **не** завершён.
- [ ] Установленная служба `zapret` (Flowseal) определяется как конфликт и не удаляется.

## 5. Редактор и импорт
- [ ] Импорт оригинального `general (ALT2).bat` — без неподдерживаемых строк; diff с
      встроенной ALT2 — «идентичны».
- [ ] Импорт `service.bat` отклоняется.
- [ ] BAT с `powershell …` — строки показаны, импорт только после галочки.
- [ ] Экспорт JSON → импорт → идентичный diff.

## 6. Трей, автозапуск, перезагрузка
- [ ] Закрытие окна сворачивает в трей (по умолчанию); меню трея работает.
- [ ] «Выход» в трее останавливает winws (при включённой настройке) и закрывает приложение.
- [ ] Автозапуск + «запускать свёрнутым» + «автоматически включать обход» → после
      перезагрузки обход активен, окно скрыто.
- [ ] Убить `discord-bridge-helper.exe` в диспетчере задач (от администратора) →
      `winws.exe` завершается вместе с ним; служба перезапускается.

## 6a. Запуск Discord
- [ ] Обход выключен, режим «с обходом» → «Запустить Discord» включает обход и
      запускает Discord.
- [ ] Обход не может запуститься (конфликт) → Discord не открывается, диалог с
      «Запустить без обхода».
- [ ] Запущен Discord PTB, выбран Stable → Stable запускается (не считается «уже запущен»).

## 7. Удаление
- [ ] Удаление останавливает свой `winws.exe`, удаляет службу и `%ProgramData%\DiscordBridge`.
- [ ] Если Discord Bridge включал TCP timestamps — предложение вернуть исходное значение.
- [ ] Автозапуск удалён у всех вошедших пользователей; чужие записи Run не тронуты.
- [ ] Discord и чужие установки Zapret не затронуты.
- [ ] Без галочки «удалить данные» стратегии в `%APPDATA%\io.github.stardely62.discordbridge` сохраняются.
- [ ] После удаления нет процессов `discord-bridge*.exe` и нашего `winws.exe`.

Результаты прикладывайте к issue по шаблону «Стратегия / провайдер» или «Ошибка».

## Обязательно: обновление NSIS и WinDivert64.sys

**Обязательно. Не закрывать без проверки на реальной Windows.**

### Симптом
При нескольких обновлениях подряд установщик NSIS показывает:

`Невозможно открыть файл для записи: C:\Program Files\Discord Bridge\flowseal\1.10.4\bin\WinDivert64.sys`

Продолжить можно только кнопкой «Пропустить». Воспроизводилось на реальной Windows.

### Установленная причина
Проверено пробой на Windows в CI, `scripts/ci/windivert-probe.ps1`.
- Драйвер WinDivert остаётся загруженным (RUNNING) после выхода winws и держит `WinDivert64.sys` закрытым для записи. Держит ядро Windows, а не процесс.
- Версии до 0.1.0-alpha.7 запускали winws, а значит и драйвер, из `Program Files\…\flowseal`.
- Переименовать файл и папку при этом можно.
- `stop_service()` игнорировал ошибку `svc.stop()`, `wait_state()` молча выходил по тайм-ауту — `--stop-engine` всегда возвращал 0.

### Исправление (PR #6)
- Проверенная остановка: коды 3 и 4, ожидание STOPPED и выхода именно нашего winws. Чужие winws не трогаются.
- Движок запускается из неизменяемой копии `ProgramData\DiscordBridge\engines\<версия>-<хэш>`.
- PREINSTALL переносит `flowseal` в `flowseal.old-*` вместо перезаписи. При неудаче ничего не меняется, служба перезапускается, пользователь получает понятное сообщение с советом перезагрузить компьютер (код 5).
- `AllowSkipFiles off`.
- Интеграция в CI (Windows Server runner), все сценарии зелёные:
  - alpha.7 → новая сборка после загрузки драйвера из Program Files;
  - переустановка;
  - эксклюзивно занятый файл: отказ 5, без смешения, затем успех;
  - `--stop-engine`;
  - удаление и чистая установка.

### Критерии закрытия (реальная Windows 10/11)
- [ ] Обновление alpha.7 → новая версия при включённом обходе, без «Пропустить».
- [ ] Три обновления подряд (в том числе той же версии) без ошибок записи.
- [ ] Обход после обновления работает: winws запущен из `ProgramData\DiscordBridge\engines\…`.
- [ ] Папки `flowseal.old-*` удаляются после следующей перезагрузки или старта службы.
- [ ] При запущенной сторонней сборке Zapret, которая держит наши файлы, установщик показывает понятное сообщение и ничего не ломает.
- [ ] Удаление проходит; остатки в `ProgramData` удаляются после перезагрузки.

# Ручное тестирование на Windows 11

Автоматические тесты проверяют логику (парсер, валидацию, рендер, diff, хранение,
подписи) и сборку. Реальная работа обхода, драйвера и голоса проверяется только вручную
на Windows 11 x64 у провайдера с DPI-блокировкой Discord.

## 1. Установка
- [ ] Установщик запускается, запрашивает права администратора, ставит в Program Files.
- [ ] `services.msc`: служба «Discord Bridge Helper» — «Выполняется», тип запуска «Автоматически».
- [ ] Ярлык в меню «Пуск»; приложение запускается **без** UAC.
- [ ] «О программе»: версии приложения, Flowseal 1.10.4, winws v72.9, служба.

## 2. Discord
- [ ] Discord найден, версия показана; при отсутствии — кнопка «Скачать Discord».
- [ ] «Запустить Discord» открывает клиент; повторное нажатие не создаёт второй экземпляр.
- [ ] Неверный путь в настройках отклоняется с понятной ошибкой.

## 3. Обход и стратегии
- [ ] Без обхода: Диагностика → HTTPS к discord.com — ошибка/тайм-аут (на заблокированной сети).
- [ ] Включить обход (general): в «Диспетчере задач» появился один `winws.exe`; Диагностика → HTTPS ✓.
- [ ] Discord загружает каналы, сообщения, картинки.
- [ ] **Голос**: зайти в голосовой канал → «Голосовая связь подключена»; слышно собеседника.
      Отметить результат кнопкой «Голос работает» / «Не работает».
- [ ] Переключение стратегии из главного окна и из трея — остаётся один `winws.exe`.
- [ ] Стратегия с ошибкой (испортить в редакторе) не запускается, показывает ошибки.
- [ ] Auto: запускается, показывает журнал, останавливается по «Отменить».
- [ ] Остановка обхода — `winws.exe` исчезает.

## 3a. Транзакции и откат (alpha.4)
- [ ] Откат после сбоя winws проверен модульными тестами (`crates/bridge-helper/src/txn.rs`).
      Надёжного способа вызвать сбой winws на реальной системе без вмешательства
      в защищённые файлы службы пока нет; если сбой встретится в работе — убедитесь,
      что показан диалог «прежняя конфигурация восстановлена» и в Диспетчере задач
      ровно один `winws.exe`.
- [ ] Переключение A → B → A несколько раз подряд: всегда один `winws.exe`,
      в `%ProgramData%\DiscordBridge\runtime` один каталог `gen-N`.
- [ ] Auto: запустить и отменить на 2-й попытке → работает исходная стратегия.
- [ ] Auto при выключенном обходе, отмена → обход остаётся выключенным.
- [ ] Во время Auto переключить стратегию в трее → отказ с объяснением.
- [ ] Закрыть приложение («Выход») во время Auto → после перезапуска пробный режим
      откатан, работает исходная конфигурация.

## 3b. Несколько пользователей
- [ ] Пользователь A включает обход. Пользователь B (без прав администратора,
      быстрое переключение пользователей) пытается выключить — отказ «управляет
      другой пользователь». B «от имени администратора» — разрешено.
- [ ] A выходит из системы → B может управлять обходом.

## 4. Конфликты
- [ ] Запустить оригинальный Flowseal `general.bat` → включить обход в Bridge →
      диалог конфликта; чужой `winws.exe` **не** завершён.
- [ ] Установленная служба `zapret` (Flowseal) определяется как конфликт и не удаляется.

## 5. Редактор и импорт
- [ ] Импорт оригинального `general (ALT2).bat` — без неподдерживаемых строк; diff с
      встроенной ALT2 — «идентичны».
- [ ] Импорт `service.bat` отклоняется.
- [ ] BAT с `powershell …` — строки показаны, импорт только после галочки.
- [ ] Экспорт JSON → импорт → идентичный diff.

## 6. Трей, автозапуск, перезагрузка
- [ ] Закрытие окна сворачивает в трей (по умолчанию); меню трея работает.
- [ ] «Выход» в трее останавливает winws (при включённой настройке) и закрывает приложение.
- [ ] Автозапуск + «запускать свёрнутым» + «автоматически включать обход» → после
      перезагрузки обход активен, окно скрыто.
- [ ] Убить `discord-bridge-helper.exe` в диспетчере задач (от администратора) →
      `winws.exe` завершается вместе с ним; служба перезапускается.

## 6a. Запуск Discord
- [ ] Обход выключен, режим «с обходом» → «Запустить Discord» включает обход и
      запускает Discord.
- [ ] Обход не может запуститься (конфликт) → Discord не открывается, диалог с
      «Запустить без обхода».
- [ ] Запущен Discord PTB, выбран Stable → Stable запускается (не считается «уже запущен»).

## 7. Удаление
- [ ] Удаление останавливает свой `winws.exe`, удаляет службу и `%ProgramData%\DiscordBridge`.
- [ ] Если Bridge включал TCP timestamps — предложение вернуть исходное значение.
- [ ] Автозапуск удалён у всех вошедших пользователей; чужие записи Run не тронуты.
- [ ] Discord и чужие установки Zapret не затронуты.
- [ ] Без галочки «удалить данные» стратегии в `%APPDATA%\io.github.stardely62.discordbridge` сохраняются.
- [ ] После удаления нет процессов `discord-bridge*.exe` и нашего `winws.exe`.

Результаты прикладывайте к issue по шаблону «Стратегия / провайдер» или «Ошибка».

## 8. Проверка обновлений

Сеть к GitHub нужна во всех пунктах, кроме 8.5. Приложение само ничего не
скачивает и не устанавливает без подтверждения; Bridge
обновляется только вручную, установщиком со страницы релиза.

### 8.1. Актуальная сборка: обновлений нет
Сборка, версия которой совпадает с последним опубликованным релизом.
- [ ] Запустить, подождать ~15 с. Уведомлений об обновлении **нет**.
- [ ] «Настройки → Обновления → Bridge»: «Обновлений нет», последняя обнаруженная = установленная, время проверки.
- [ ] Flowseal: активная 1.10.4, последняя официальная — текущий релиз Flowseal. Если он тоже 1.10.4 — «Обновлений нет», «Подписанный манифест: не требуется».
- [ ] «О программе → Проверить обновления»: «Установлена последняя версия», кнопки «Открыть релиз» нет.

### 8.2. Старая сборка: найдена новая версия
Тестовая сборка с версией ниже опубликованной (например, ветка-проба с версией
`0.1.0-alpha.9`; в репозиторий она не вливается).
- [ ] Через ~15 с после запуска внизу справа: «Доступна новая версия Bridge — …» с кнопками «Открыть релиз» и «Позже».
- [ ] «Открыть релиз» открывает в браузере **страницу именно этого релиза** (`…/releases/tag/v…`), а не список релизов.
- [ ] «Позже» убирает уведомление. Переходы по вкладкам и повторная проверка в «Настройках» не показывают его снова. После перезапуска приложения оно появится снова (подавление — на сессию).
- [ ] «Настройки → Обновления»: «Доступна новая версия», номер, заметки к релизу, кнопка «Открыть релиз …».

### 8.3. Запуск свёрнутым
- [ ] Включить «Сворачивать при запуске» (или запустить с `--minimized`), запустить тестовую сборку из 8.2, окно не открывать.
- [ ] Через ~15 с подсказка значка в трее содержит «Доступно обновление: Bridge …».
- [ ] Открыть окно из трея: уведомление на месте, повторной проверки не требуется.

### 8.4. Настройка выключена
- [ ] «Настройки → Обновления»: выключить «Автоматически проверять обновления при запуске», перезапустить.
- [ ] Уведомлений нет; в «Обновлениях» статус «Не проверялось» у обоих компонентов. Ручная проверка работает.
- [ ] Перезапуск: переключатель по-прежнему выключен. Включить обратно.

### 8.5. Нет сети
- [ ] Отключить сеть, запустить. Обход и Discord запускаются как обычно, без задержек и без всплывающих ошибок.
- [ ] «Настройки → Обновления»: у обоих компонентов «Ошибка проверки» с понятной причиной (нет соединения / тайм-аут). Никаких «установлена последняя версия».
- [ ] Включить сеть, «Проверить» — статус обновляется.

### 8.6. Flowseal (только автоматически)
Новее 1.10.4 официального релиза Flowseal сейчас нет, поэтому на реальной
Windows не проверить:
- уведомление «Доступен Flowseal X» и установку из «Обновлений»;
- уведомление «Вышел Flowseal X, но его пакет ещё не проверен для Bridge» (без кнопки установки);
- откат при неудачном переключении.

Эти сценарии покрыты тестами с локальным HTTP-сервером и подписанными
тестовыми манифестами (`crates/bridge-updates`, `crates/bridge-core/src/updates`).
Установка и проверка в службе — тестами `crates/bridge-helper` (подпись, хеши,
неверный ключ). Когда выйдет новый Flowseal, пройти вручную:
- [ ] до публикации нашего манифеста — уведомление «…ещё не проверен…», в «Обновлениях» «Обновление пока недоступно» и причина, кнопки установки нет;
- [ ] после публикации — «Доступен Flowseal X», «Перейти к обновлению» открывает «Обновления», установка с подтверждением, статус «Установка завершена», в списке версий прежняя версия с кнопкой «Использовать».

## 9. Telegram WS Proxy (Telegram Desktop)

Отмечать только то, что реально проверено; результат звонков записывать как есть.

### 9.1. Установка и запуск
- [ ] Чистая установка и обновление поверх alpha.10: в `Program Files\Bridge\tg-ws-proxy\` лежат `discord-bridge-tg-ws-proxy.exe`, `tg-ws-proxy.json` и лицензии; настройки сохранились.
- [ ] Карточка «Telegram»: «выключен», версия 1.11.4. «Запустить» → «ждёт подключения», адрес 127.0.0.1:1443.
- [ ] Нет второго значка в трее, нет окна консоли. В диспетчере задач — процессы `discord-bridge-tg-ws-proxy.exe` (загрузчик и Python) от имени пользователя, не администратора.
- [ ] Порт 1443 занят другой программой → понятная ошибка, та программа продолжает работать. Смена порта в настройках → запуск на новом порту.

### 9.2. Подключение Telegram Desktop
- [ ] «Подключить Telegram» → Telegram предлагает добавить прокси, после подтверждения в Telegram «Подключено».
- [ ] Без Telegram Desktop — инструкция ручного подключения, а не ложный успех.
- [ ] Карточка: «Telegram подключён», маршрут «WebSocket напрямую»; диагностика — клиент и обмен данными «ok».
- [ ] Авторизация (вход в аккаунт через прокси).
- [ ] Отправка и получение сообщений.
- [ ] Загрузка фотографий (получение и отправка).
- [ ] Загрузка видео (просмотр и отправка).
- [ ] Отправка файлов.
- [ ] Звонки: прокси передаёт только MTProto по TCP. Голосовые и видеозвонки Telegram идут по UDP отдельно от прокси и через него не проходят. Записать фактический результат: работают ли звонки и при каком состоянии Zapret.

### 9.3. Независимость от Zapret
- [ ] Прокси включён, Zapret выключен — Telegram работает.
- [ ] Включить Zapret → прокси продолжает работать; диагностика «Пересечение с Zapret».
- [ ] Выключить Zapret → прокси работает. Остановить прокси → Zapret (Discord) работает.
- [ ] Оба выключены / оба включены — без ошибок в карточках.

### 9.4. Перезапуски и сеть
- [ ] Сворачивание в трей — прокси работает. Полный выход — процессы прокси исчезают.
- [ ] Автозапуск прокси включён, автовключение обхода выключено → после перезапуска Bridge запускается только прокси.
- [ ] После остановки прокси Telegram показывает «Подключение…»; подсказка в Bridge объясняет, как вернуть прямое соединение.
- [ ] Отключить интернет при работающем прокси → Telegram «Подключение…», прокси не падает. Включить интернет → соединение восстанавливается.
- [ ] Смена секрета → старая ссылка перестаёт работать (диагностика: «неверный секрет»), новая подключается.
- [ ] После успешного сеанса закрыть Telegram, затем подключиться со старой ссылкой (неверный секрет) → карточка «ждёт подключения», не «Telegram подключён».
- [ ] При работающем прокси сменить порт в настройках, не перезапуская → карточка показывает прежний порт и подсказку о перезапуске; «Подключить Telegram» и скопированная ссылка указывают на работающий порт; после перезапуска — на новый.
- [ ] `icacls "%APPDATA%\io.github.stardely62.discordbridge\telegram-proxy.secret"` — только текущий пользователь, SYSTEM и Администраторы, без унаследованных записей. Содержимое файла не выводить и не публиковать.
- [ ] Резервный маршрут через Cloudflare включён → маршрут в карточке меняется, только если прямой WebSocket недоступен.

## Обязательно: обновление NSIS и WinDivert64.sys

**Обязательно. Не закрывать без проверки на реальной Windows.**

### Симптом
При нескольких обновлениях подряд установщик NSIS показывает:

`Невозможно открыть файл для записи: C:\Program Files\Bridge\flowseal\1.10.4\bin\WinDivert64.sys`

Продолжить можно только кнопкой «Пропустить». Воспроизводилось на реальной Windows.

### Установленная причина
Проверено пробой на Windows в CI, `scripts/ci/windivert-probe.ps1`.
- Драйвер WinDivert остаётся загруженным (RUNNING) после выхода winws и держит `WinDivert64.sys` закрытым для записи. Держит ядро Windows, а не процесс.
- Версии до 0.1.0-alpha.7 запускали winws, а значит и драйвер, из `Program Files\…\flowseal`.
- Переименовать файл и папку при этом можно.
- `stop_service()` игнорировал ошибку `svc.stop()`, `wait_state()` молча выходил по тайм-ауту — `--stop-engine` всегда возвращал 0.

### Исправление (PR #6)
- Проверенная остановка: коды 3 и 4, ожидание STOPPED и выхода именно нашего winws. Чужие winws не трогаются.
- Движок запускается из неизменяемой копии `ProgramData\DiscordBridge\engines\<версия>-<хэш>`.
- PREINSTALL переносит `flowseal` в `flowseal.old-*` вместо перезаписи. При неудаче ничего не меняется, служба перезапускается, пользователь получает понятное сообщение с советом перезагрузить компьютер (код 5).
- `AllowSkipFiles off`.
- Интеграция в CI (Windows Server runner), все сценарии зелёные:
  - alpha.7 → новая сборка после загрузки драйвера из Program Files;
  - переустановка;
  - эксклюзивно занятый файл: отказ 5, без смешения, затем успех;
  - `--stop-engine`;
  - удаление и чистая установка.

### Критерии закрытия (реальная Windows 10/11)
- [ ] Обновление alpha.7 → новая версия при включённом обходе, без «Пропустить».
- [ ] Три обновления подряд (в том числе той же версии) без ошибок записи.
- [ ] Обход после обновления работает: winws запущен из `ProgramData\DiscordBridge\engines\…`.
- [ ] Папки `flowseal.old-*` удаляются после следующей перезагрузки или старта службы.
- [ ] При запущенной сторонней сборке Zapret, которая держит наши файлы, установщик показывает понятное сообщение и ничего не ломает.
- [ ] Удаление проходит; остатки в `ProgramData` удаляются после перезагрузки.

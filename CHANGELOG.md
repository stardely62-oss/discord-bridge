# Changelog

## [0.1.0-alpha.10] — не выпущена

Первая версия в новом публичном репозитории. Новых пользовательских функций нет: всё из alpha.9 плюс изменения ниже. История alpha.1–alpha.9 и их релизы остались в приватном архиве; описания этих версий сохранены ниже.

### Безопасность
- **Новый ключ подписи манифестов Flowseal.** Приложение доверяет только ему. Манифесты, подписанные прежним ключом, не принимаются: нужные версии перевыпущены новым ключом с теми же хешами официальных архивов. Уже установленные версии Flowseal не затрагиваются — они проверяются по хешам файлов.
- `scripts/keys/flowseal-key.mjs`: генерация пары на компьютере владельца (seed не выводится на экран) и проверка соответствия seed закреплённому открытому ключу.

### Безопасность (инфраструктура)
- Все GitHub Actions закреплены по полному SHA; `tauri-action` заменён на `pnpm tauri build` и отдельный job публикации.
- Подпись манифестов Flowseal вынесена в отдельный job в окружении `flowseal-sign`: только встроенный Node и подписант без зависимостей, подписывается payload с хешем из job сборки, результат проверяется Rust-верификатором до публикации.
- Release разделён на gate, build (только чтение, проверка содержимого NSIS) и publish (единственный job с записью; существующий релиз не заменяется, `--clobber` убран).
- CI-job «Security»: gitleaks (закреплённый бинарь), поиск приватных seed закреплённых ключей во всей истории, проверка noreply-почты новых коммитов (маскированно), политика workflow.
- Расширен `.gitignore` для секретов; `docs/release-security.md`.

## [0.1.0-alpha.9] — 2026-11-06

### Добавлено
- **Удалённый каталог приложений и сервисов** из отдельного репозитория `discord-bridge-catalog`.
  - **Подпись.** Ed25519 с отдельным ключом каталога. Проверяются подпись, хэши, лимиты, наборы и значки. Более старый каталог не принимается.
  - **Офлайн.** Без связи используется последний проверенный каталог, а если его нет — встроенный снимок.
- **Значки сервисов** — из Simple Icons, источники и права описаны в репозитории каталога.
- **Каталог в интерфейсе:** поиск, категории, детали набора (домены, IP, происхождение, версия, дата).
- **Работа с наборами:**
  - обновление показывает точную разницу адресов и требует подтверждения;
  - перед обновлением сохраняется предыдущая версия, к ней можно откатиться;
  - наборы, исчезнувшие из каталога, сохраняются локально.
- **Встроенный снимок** — это опубликованный каталог `catalog-1793927940` вместе с его подписанным манифестом; тесты проверяют подпись закреплённым ключом без сети.
- **Сетевая проверка опубликованного каталога** вынесена отдельно от офлайн-тестов: отдельный workflow «Published catalog» и информационный шаг Windows CI.

### Безопасность
- **Подтверждение привязано к точному снимку набора.** Раньше установка проверяла только номер версии: если фоновая синхронизация получала каталог с той же версией набора, но другими адресами, могли сохраниться адреса, которых пользователь не видел. Теперь подтверждение содержит id, версию, serial каталога, SHA-256 набора и SHA-256 установленной копии. Rust проверяет их и сохраняет ровно проверенный набор в одной критической секции. Если что-то изменилось — ничего не меняется и предлагается посмотреть изменения ещё раз.
- Окна обновления и деталей набора не подменяют показанные данные данными нового каталога: появляется предупреждение, кнопка подтверждения недоступна до повторного просмотра.

### Совместимость
- Наборы, установленные в alpha.8, сохраняются без изменений. Сравнение идёт по содержимому, новые адреса автоматически не ставятся.
- `InstalledPack` получил необязательные поля `title` и `previous`.

## [0.1.0-alpha.8] — 2026-11-05

### Исправлено
- **Иконка в exe.** Иконку exe, окна и панели задач Tauri компилирует из `icons/icon.ico` в build-скрипте, но не перезапускает его при изменении только иконки. С кэшем `target` в CI такой коммит мог собрать exe со старой иконкой. Теперь `build.rs` перезапускается при изменениях в `icons/`, а иконка установщика NSIS задана явно.
- **Проверка в CI.** CI и релиз сверяют иконку побайтово с `icon.ico` в собранном `discord-bridge.exe` и в exe, распакованном из установщика (`scripts/check-exe-icon.py`).

- **Обновление через NSIS** («Невозможно открыть файл для записи … WinDivert64.sys»).
  - **Причина.** До alpha.7 winws запускался прямо из `Program Files\Discord Bridge\flowseal`, поэтому драйвер WinDivert загружался ядром из этого файла. Он остаётся загруженным после выхода winws, и файл занят до перезагрузки — это подтверждено на Windows в CI. Вдобавок `--stop-engine` игнорировал ошибку остановки и тайм-аут и всегда возвращал 0.
  - **Исправление:**
    - остановка проверяется по-настоящему: коды 3 и 4, ожидание STOPPED и завершения именно нашего winws, чужие процессы не трогаются;
    - служба запускает движок из неизменяемой копии `ProgramData\DiscordBridge\engines\<версия>-<хэш>`;
    - установщик переносит старую папку `flowseal` в сторону, а не перезаписывает её. Если перенос невозможен, ничего не меняется, служба перезапускается и пользователю советуют перезагрузить компьютер;
    - кнопка «Пропустить» отключена (`AllowSkipFiles off`).

### Добавлено
- **IP-наборы.**
  - Ручной список «IP через обход» и IP-подсети в наборах каталога (IPv4 и IPv6). Набор Telegram содержит официальные подсети из `core.telegram.org/resources/cidr.txt`.
  - Новые режимы «Какие IP идут через обход»: без IP, выбранные IP, полный список Flowseal, Flowseal + выбранные, все адреса (помечен как рискованный).
  - Исключения важнее всего и вычитаются из подсетей точно, даже при частичном пересечении (`10.0.0.0/8` минус `10.1.0.0/16`). В режиме «Все адреса» с исключениями пишется явное «все минус исключения». Пустая выборка никогда не превращается в «все адреса».
  - Статус IP показан по шагам: набор установлен → IP в подготовленной конфигурации → стратегия использует IP-фильтры → работающий обход использует эту конфигурацию. «Используются обходом» — только когда подтверждены все шаги.
- **Честные предупреждения.** Каталог и ручные списки предупреждают, если текущий режим не применит IP набора.

- **Интеграционные проверки установщика на Windows в CI:**
  - обновление с настоящего alpha.7 после загрузки драйвера из `Program Files`;
  - повторная установка;
  - чужой эксклюзивный дескриптор (понятный отказ, без смешения версий);
  - проверка `--stop-engine`;
  - удаление и чистая установка.

### Совместимость
- Старые настройки читаются без миграции: новые поля пустые, `loaded` читается как `flowseal`.
- Версия протокола IPC — 3: приложение и служба ставятся вместе.
- Подтверждения голоса, сделанные в режиме `loaded`, придётся подтвердить заново: хэш конфигурации теперь включает новое имя режима.

## [0.1.0-alpha.7] — 2026-11-05

### Интерфейс (Design v4)
- **Главная.**
  - Крупный блок Discord с одной главной кнопкой «Запустить Discord» и статусом простыми словами.
  - Вторичные действия убраны под «Ещё»: подбор, смена стратегии, выключение обхода, проверка, диагностика, каталог.
  - Ниже две карточки: **Zapret** — общий движок обхода (стратегия, подключённые приложения, свои адреса, предупреждение «изменения не применены») и **Telegram** — полноценная карточка модуля с состояниями «скоро» и «активен».
- **Стратегии.**
  - Вкладки «Встроенные», «Сообщество», «Мои», «Импорт».
  - У встроенных стратегий есть понятная пометка: базовая, альтернативная, для проблемных сетей, упрощённая, экспериментальная, не рекомендуется.
  - Вкладка «Сообщество» пока честно пустая: каталог с GitHub не подключён.
- **«Приложения и списки»** вместо «Списков».
  - Каталог официальных наборов: Discord, YouTube, Telegram, Steam, Riot Client, Valorant, Epic Games, Battle.net, Roblox, Twitch.
  - Установленные наборы хранятся отдельно от ваших адресов (`installedPacks`) и смешиваются с ними только при сборке конфигурации движка. Удаление набора убирает только его вклад: ваши строки и адреса, нужные другому набору, остаются.
  - Статусы: «входит в Flowseal», «установлен», «отличается от каталога», «не установлен». Для игр и Telegram карточка прямо предупреждает, что домены помогают частично.
  - Вкладки «Мои приложения» и «Ручные списки» с импортом и экспортом `.txt`.
- **Диагностика** начинается с человеческого резюме, технические подробности раскрываются отдельно.
- **Настройки.** Системные настройки Windows помечены.
- **Новый утверждённый логотип**: разрезанный «пузырь» чата. Иконка приложения, ICO на 16–256 px, знак в боковой панели (отдельные версии для тёмной и светлой темы) и иконки трея (знак + индикатор состояния). Исходники в `assets/brand/`.

### Добавлено
- `Overview.pendingApply`: обход работает со старой конфигурацией (сравниваются хэши `config_hash`, учитываются и наборы каталога).
- Настройка `installedPacks` (по умолчанию пустая; старые файлы настроек читаются без миграции) и `bridge_core::lists::effective_lists` / `validate_packs`.
- Команды `read_list_file` / `write_list_file` для ручных списков (до 1 МБ, UTF-8).

## [0.1.0-alpha.6] — 2026-11-05

### Исправлено (критично для alpha.5)
- Клиент приложения открывал новое соединение со службой и сразу отправлял
  команду, а служба alpha.5 требует `Hello` первым сообщением на каждом
  соединении. Поэтому Status, Start, Stop, Diagnose и большинство других команд
  отклонялись с ошибкой «первым сообщением должен быть Hello». Теперь
  единственная функция связи со службой (`HelperClient::call`) после проверки
  владельца канала выполняет `Hello`, проверяет версию протокола и только затем
  отправляет команду по тому же соединению. При неудачном рукопожатии команда не
  отправляется, а ошибка понятна (версия, отказ в доступе, сбой связи).

### Добавлено
- Сквозной тест для Windows: настоящий `HelperClient` приложения против настоящего
  сервера службы на named pipe — Hello, Status, ListBundles, серия вызовов
  (по рукопожатию на каждое соединение), несовпадение протокола, неавторизованный
  клиент, команда без Hello, а также вызов из неповышенного (LUA) процесса.

### Интерфейс
- Главная переработана для тех, кто не разбирается в технических деталях:
  блок **Discord** с понятным статусом («Всё готово», «Обход включён, но Discord
  не открывается» и т. п.), одной главной кнопкой «Запустить Discord» и тремя
  проверками: доступ к Discord, голосовые каналы, способ обхода. «Подобрать
  автоматически» теперь запускает подбор прямо на главной, с прогрессом и отменой.
  Ниже зарезервирован блок **Telegram** («скоро»).
- «Доступ к Discord» на главной и в диагностике считается одинаково: «частично»,
  если не отвечает часть адресов Discord.
- Новый раздел **«Списки»**: свои списки адресов (через обход / не трогать / IP)
  перенесены из настроек; место под будущие готовые наборы с GitHub.
- Настройки и диагностика разбиты на вкладки, описания сокращены.
- Стратегии: обзор правил без россыпи плашек, требование TCP timestamps —
  значок в шапке, переключатель перенесён из блока перехвата; действия с правилом
  убраны в меню «⋯»; JSON-редактор без переносов строк, с панелью инструментов и
  предпросмотром аргументов по правилам; импорт и шаблоны — в меню «⋯».
- Все системные окна `window.confirm` заменены окнами в стиле приложения;
  свои чекбоксы и числовые поля; правильные склонения («1 правило», «5 правил»).
- Светлая тема (по умолчанию — как в Windows), скелетоны загрузки, уведомления
  больше не перекрывают панель «Сохранить».
- Новая иконка приложения; иконка в трее показывает, включён ли обход; меню трея
  переводится вместе с интерфейсом.

## [0.1.0-alpha.5] — 2026-11-05

### Исправлено (критично для alpha.4)
- Служба alpha.4 вызывала `ImpersonateNamedPipeClient` до чтения данных из канала;
  по контракту Windows это завершается `ERROR_CANNOT_IMPERSONATE`, поэтому любой
  клиент отклонялся. Теперь первым читается ограниченный кадр (только `Hello`,
  ничего не выполняется), затем проверка образа клиента и олицетворение, и лишь
  после этого — ответ и дальнейшие команды.
- `--tcp-changed` / `--restore-tcp` (вызываются деинсталлятором при работающей
  службе) создавали контроллер движка и удаляли каталоги `runtime/gen-*`.
  Обслуживание TCP теперь работает только с файлом состояния.

### Добавлено
- Интеграционный тест для Windows: неповышенный клиент (LUA-токен) проходит
  Hello и Status; чужой exe и запрос без Hello отклоняются.

## [0.1.0-alpha.4] — 2026-11-05

### Исправлено
- Смена стратегии больше не останавливает рабочий winws до полной подготовки новой;
  списки готовятся в отдельном каталоге поколения; откат — на точный снимок
  (включая перезапуск отредактированной стратегии с тем же ID).
- Auto при отмене, тайм-ауте, ошибке службы или неудаче восстанавливает исходное
  состояние (в том числе «обход выключен»); ручные операции во время Auto отклоняются.
- Пустой или неполный набор HTTPS-проверок больше не считается успехом; критерий
  Auto — корректный ответ Discord API.
- Подтверждение голоса привязано к хэшу эффективной конфигурации.
- Настройки сохраняются атомарно до изменения состояния в памяти; автозапуск
  Windows проверяется и откатывается при ошибке.
- Импорт: повторный разбор оригинала по серверному токену; сохранение черновиков
  с проверкой безопасности данных.
- Discord: Stable/PTB/Canary больше не путаются.
- Сравнение версий: SemVer для приложения, документированная схема для Flowseal;
  `minAppVersion` проверяется.
- Установщик: ошибка регистрации службы прерывает установку; служба обновляется
  на месте, а не удаляется; автозапуск удаляется только у записей с нашим путём.

### Добавлено
- Единая команда «Запустить Discord» с выбором режима.
- Политика владельца сетевого состояния для нескольких пользователей Windows,
  лимиты соединений службы, чтение архива обновления под олицетворением.
- Транзакционная смена версии Flowseal с отчётом совместимости.
- Запись исходного значения TCP timestamps и восстановление.
- Шаблон «Discord Only».
- Релиз собирается только при успешном CI того же коммита и совпадении версий.

Первая техническая alpha-сборка.

### Добавлено
- Лаунчер официального Discord (поиск Stable/PTB/Canary, свой путь, запуск, статус).
- Встроенный Flowseal 1.10.4 (winws v72.9): все 22 стратегии с сохранением точного порядка аргументов.

# Политика безопасности

## Сообщить об уязвимости

Не создавайте публичный issue. Используйте приватный отчёт GitHub
(**Security → Report a vulnerability**) в этом репозитории. Мы ответим в течение 7 дней.

## Модель угроз (кратко)

| Угроза | Защита |
|---|---|
| Выполнение команд из импортированного BAT | BAT только парсится; поддерживается узкое подмножество синтаксиса; `& | < >` вне кавычек, неизвестные переменные и пути вне `bin/`/`lists/` отклоняются; неподдерживаемые строки импортируются только с явного согласия и никогда не выполняются |
| Подмена аргументов winws (shell injection) | значения проходят строгую типовую валидацию в UI и повторно в службе; процесс создаётся без оболочки (`CreateProcess`), кавычки/`%`/`^`/`&`/`|`/пробелы в значениях запрещены |
| Path traversal через ресурсы | ресурсы задаются только именем (`[A-Za-z0-9._-]`), без разделителей и `..`; служба подставляет каталог сама |
| Запуск чужого исполняемого файла | исполняемый файл всегда `bin/winws.exe` активного бандла; SHA-256 движка, DLL и драйвера сверяется с манифестом через удерживаемые дескрипторы |
| Подмена бандла при обновлении | подписанный Ed25519 манифест + хэш архива из манифеста + хэш каждого файла; повторная проверка в службе; источник — только официальный GitHub Flowseal |
| Неавторизованный клиент службы | DACL канала, отказ удалённым клиентам, проверка пути образа клиента; неизвестные команды не десериализуются |
| Другой пользователь Windows управляет чужим обходом | владелец сетевого состояния по SID из токена клиента (олицетворение); управление — владельцу, администратору или после выхода владельца |
| Истощение ресурсов службы | ≤ 8 одновременных клиентов, 90 с на соединение, кадр ≤ 1 МБ |
| Чтение чужих файлов через установку обновления | файл архива открывается под олицетворением клиента, ≤ 64 МБ, затем проверяется подпись и хэши |
| Потеря рабочего соединения при смене стратегии | подготовка в отдельном каталоге поколения до остановки старого движка, откат на точный снимок |
| Подмена канала службы | `FILE_FLAG_FIRST_PIPE_INSTANCE`; служба задаёт владельца SYSTEM; клиент требует владельца SYSTEM или «Администраторы» |
| Подготовленный злоумышленником каталог данных службы | `%ProgramData%\DiscordBridge` с чужим владельцем переименовывается; DACL защищён (SYSTEM + Администраторы) |
| Осиротевший процесс winws | Job Object `KILL_ON_JOB_CLOSE` |
| Утечки в журналах | маскирование путей профиля и имени пользователя, маска похожих на токены строк, лимит размера |

## Что Discord Bridge не делает

Не изменяет Discord, не внедряет DLL, не читает токены, сообщения и учётные данные,
не меняет hosts/DNS/брандмауэр, не отключает средства защиты Windows. Единственное
системное изменение — TCP timestamps — выполняется только по явному согласию,
проходит политику владельца службы, исходное значение записывается и может быть
восстановлено (в настройках и при удалении), но только если его с тех пор никто
не менял.

## Не проверено

Модель авторизации покрыта модульными тестами политики; работа олицетворения,
нескольких сеансов Windows и ограничений соединений на реальной системе не
проверялась. Конкретные уязвимости повышения привилегий не подтверждались и не
заявляются как устранённые.

## Каталог приложений

- Каталог содержит только данные: домены, IP-сети, тексты, PNG/WebP-значки. Исполняемые файлы, скрипты и параметры winws через него не передаются.
- **Доверие.** Подпись Ed25519 проверяется отдельным закреплённым ключом (`CATALOG_TRUSTED_KEYS`). Он не принимает манифесты Flowseal, а ключ Flowseal не принимает каталог.
- **Ключ подписи.** Приватный ключ хранится только в секрете окружения `catalog-publish` репозитория каталога. Окружение требует одобрения владельца и разрешено только для `main`.
- **Загрузка.** Адреса загрузки фиксированы в приложении, ответы ограничены по размеру и времени. Данные принимаются только после полной проверки. Номер публикации не может уменьшиться.
- **Осознанное подтверждение.** Установка и обновление набора привязаны к точному показанному снимку (serial каталога, SHA-256 набора и установленной копии). Если каталог сменился между просмотром и подтверждением, ничего не устанавливается — пользователь смотрит изменения заново.
